Fix `uniharmony.datasets.make_multisite_classification`: `signal_type="gaussian_quantiles"` (the documented name) raised an error; when the class proportions or the sizes of the sites differed, base samples were silently drawn with replacement (up to 45% duplicated samples, leaking between train and test), now the pool always has the needed class counts; class counts are rounded with the largest-remainder method, so a class with proportion 0 gets no samples; sampling is now linear in the number of samples (40 000 samples: 19 s → 0.05 s); per-site strengths of 0, NumPy integers and arrays for `n_samples`, and integer or array class proportions are accepted, and a site with 0 samples raises an error. Covariates: the user's `Covariate` is no longer modified, so it can be reused with another `n_sites`.
