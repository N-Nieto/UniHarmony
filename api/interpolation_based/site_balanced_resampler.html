SiteBalancedResampler#

class uniharmony.interpolation.SiteBalancedResampler(oversampler: IntraSiteInterpolation | None = None, undersampler: str | Literal['random', 'nearmiss', 'nearmiss-1', 'nearmiss-2', 'nearmiss-3', 'cluster-centroids', 'instance-hardness'] | SamplerMixin = 'cluster-centroids', undersampler_kwargs: dict | None = None, max_amplification: float | str | Literal['auto'] | Callable[[ndarray], float] | None = 'auto', random_state: int | RandomState | None = None)#

Balance the classes within every site by over-sampling and under-sampling.

SiteBalancedResampler combines a within-site over-sampler, IntraSiteInterpolation (ISI, with any interpolator, including "random" duplication), with an imblearn under-sampler. Over-sampling is limited to at most max_amplification synthetic samples per real sample of a class; the remaining imbalance is closed by under-sampling the larger classes of the site, so both meet in the middle. As with ISI alone, every class then has the same number of samples in a site and the site no longer predicts the target.

For each site s with n_sc real samples in class c:

  1. The site target n_max is the largest class of the site, of any site, or a given number (the balance_strategy of the over-sampler).

  2. Each class below n_max gets a cap r_sc (max_amplification) and the site target becomes T_s = min(n_max, min_c floor(n_sc * (1 + r_sc))).

  3. Classes above T_s are reduced to T_s real samples with undersampler (stratified by covariates).

  4. The over-sampler brings the classes below T_s up to T_s.

max_amplification=0 gives pure within-site under-sampling and max_amplification=None gives the over-sampler alone.

Parameters:
oversamplerIntraSiteInterpolation or None, optional (default None)

Within-site over-sampler. None means IntraSiteInterpolation(random_state=random_state) (SMOTE). Its balance_strategy, binning and covariate options are used for the whole procedure. Use IntraSiteInterpolation("random") for within-site duplication.

undersamplerstr or imblearn under-sampler, optional (default “cluster-centroids”)

Under-sampler for the classes above the capped site target. Strings: "cluster-centroids" (k-means on the class, keeping the real sample closest to each centroid, i.e. ClusterCentroids(voting="hard"), so the kept samples cover the whole class), "nearmiss" ("nearmiss-1"), "nearmiss-2", "nearmiss-3", "instance-hardness" or "random". Any imblearn under-sampler that selects real samples and accepts a target count per class (dict sampling_strategy) can be passed. Cleaning methods (Tomek links, ENN, …) cannot reach an exact count, and prototype generators (ClusterCentroids(voting="soft")) create new samples; both are rejected.

undersampler_kwargsdict or None, optional (default None)

Keyword arguments for undersampler when it is given as a string.

max_amplificationfloat, “auto”, callable or None, optional (default “auto”)

Maximum number of synthetic samples per real sample of a class.

  • "auto": the safe amplification of each class from the variance rule of the over-sampler (see IntraSiteInterpolation.variance_tolerance), measured on all real samples of the site before anything is removed.

  • float >= 0: the same cap for every class (0 means pure under-sampling).

  • callable: f(X_cell) -> float returning the cap of a class from its real samples.

  • None: no cap (the over-sampler alone; nothing is removed).

random_stateint, RandomState instance or None, optional (default None)

Seed for the under-sampler and for the pilot draws of max_amplification="auto" (and for the default over-sampler). A given over-sampler uses its own random_state.

Notes

The same rules as for ISI apply: resample training data only, and tune hyper-parameters with the resampler inside the inner cross-validation.

With many features and a strong imbalance, up-weighting methods (ISI, random over-sampling, re-weighting) leave part of the site-target association in models that can fit individual samples, whereas under-sampling does not but discards data. The cap trades one for the other; check the remaining association by repeating the cross-validation after permuting the target within each site, and look at samples_removed_: when most samples of a site must be removed, the imbalance is beyond what within-site balancing can repair without losing information.

set_fit_resample_request(*, categorical_covariate: bool | None | str = '$UNCHANGED$', continuous_covariate: bool | None | str = '$UNCHANGED$', sites: bool | None | str = '$UNCHANGED$') → SiteBalancedResampler#

Configure whether metadata should be requested to be passed to the fit_resample method.

Note that this method is only relevant when this estimator is used as a sub-estimator within a meta-estimator and metadata routing is enabled with enable_metadata_routing=True (see sklearn.set_config()). Please check the User Guide on how the routing mechanism works.

The options for each parameter are:

  • True: metadata is requested, and passed to fit_resample if provided. The request is ignored if metadata is not provided.

  • False: metadata is not requested and the meta-estimator will not pass it to fit_resample.

  • None: metadata is not requested, and the meta-estimator will raise an error if the user provides it.

  • str: metadata should be passed to the meta-estimator with this given alias instead of the original name.

The default (sklearn.utils.metadata_routing.UNCHANGED) retains the existing request. This allows you to change the request for some parameters and not others.

Added in version 1.3.
